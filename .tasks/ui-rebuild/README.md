# UI 重构任务区

这个目录只放 **UI 重构** 的任务，与仓库主任务注册表 [`.tasks/tasks.yaml`](../tasks.yaml) **分开维护**：
主注册表里的卡片（TASK-0xx）承接的是"产品能力/后端契约"这条线，本轮 UI 重构是**独立的、跨多张卡的结构工程**，
混在一起会让主注册表的依赖图变脏，也不方便并行推进。

## 目录约定

| 文件 | 作用 |
| --- | --- |
| `tasks.yaml` | UI 任务卡（唯一的 UI 任务来源） |
| `README.md` | 本文件：口径、状态定义、与主注册表的关系 |

历史验收证据仍然按主约定留在 `.tasks/verification/`、交接记录留在 `.tasks/memory/`，
本目录**不放**证据与交接（避免同一件事两处记账）。

## 状态定义

- `pending`：未开始
- `ready`：依赖已满足，可以领
- `in_progress`：在做
- `blocked`：被上游决策或外部条件卡住（须在卡内写明卡在哪）
- `done`：**已集成并验收**（构建/机核/真机，三者不可用"应该能跑"替代）

## 与主注册表的关系

- 主注册表卡片的**契约类结论仍以它为准**（例如桥的方法数、协议版本、路由表）。
- 本文档的所有结构口径以 [`apps/app/ARCHITECTURE.md`](../../apps/app/ARCHITECTURE.md) 为准；那份文档是 UI 结构的**唯一权威**，本目录的卡只引用它，不重复描述结构。

## 文件级落点

每张卡带 `touches` 字段，列出**要新增/修改/归档的文件**（相对仓库根），
实施者不需要再从零推断落点；`touches` 与验收判据不一致时，以验收判据为准并更新卡片。
